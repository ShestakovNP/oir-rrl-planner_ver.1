# ОИР RRL Planner

Десктопная программа ОИР (Отдел инфраструктурных решений) для расчёта пролётов радиорелейных линий: карта объектов, профиль трассы, бюджет линии, надёжность, выбор поляризации, рекомендации и PDF-отчёты.

- Работает на **macOS** (10.15+, Intel и Apple Silicon) и **Windows** 10/11.
- **Ничего не нужно активировать**: нет ключей, лицензий, регистрации и логинов. Программа просто запускается.
- **Данные хранятся на компьютере пользователя** (SQLite). Собственных серверов, аналитики и трекеров нет.
- **Интернет нужен только для карты, поиска мест и загрузки рельефа.** Расчёты, данные, экспорт и отчёты работают без сети.

## Что умеет

| Раздел | Возможности |
|---|---|
| Проекты | Несколько проектов, переименование, удаление, экспорт и импорт (JSON) |
| Обмен между инженерами | Кнопки «Экспорт проекта» и «Импорт проекта» под выбором проекта. В файл .json попадают объекты, пролёты со всеми исходными данными и профилями, ППУ и антенны, плюс комментарий для коллеги. Когда проект возвращается, программа узнаёт его и предлагает «Обновить проект» (прежняя версия сохраняется в папку настроек) или «Сохранить копией» |
| Объекты | Добавить кликом по карте или по координатам (десятичные или °′″), перетаскивание, номер БС, заметки, импорт и экспорт CSV для Excel |
| Пролёты | Создание из списка или выбором двух объектов на карте; цвет линии показывает итог (зелёный — норма, оранжевый — не везде, красный — нет связи) |
| Профиль | Автозагрузка рельефа SRTM 30 м, зданий, лесов и водоёмов из OpenStreetMap (высота здания по карте или типовая, высота леса задаётся); на графике здания, лес и вода выделены своими цветами; ручная правка с типом точки (З/Л/В), вставка из Excel/DRRL; сохранение графика в PNG и JPEG; курсор на линии пролёта на карте и на графике синхронизирован и показывает просвет и зону Френеля в этой точке |
| Расчёт | До двух стволов на одной антенне (разные диапазоны и поляризации), мощность и пороги ППУ по режимам, развязка поляризаций, просвет, дифракция, газы, дождь, многолучёвость, отражение от водной глади (интерференция, рассеяние на волнах, поглощение), неготовность |
| Помехи на узле | Пролёты, выходящие с одного объекта на перекрывающихся частотах: помеха от дальнего передатчика через боковые лепестки антенны (диаграмма МСЭ-R F.699), учёт поляризации и XPD, ухудшение порога в запасе, рекомендации |
| Резервирование | Схемы 1+0, 1+1 HSB (горячий резерв), 1+1 SD (разнесённый приём: вторая антенна на объекте на другой высоте), 1+1 FD (частотное разнесение); выигрыш по МСЭ-R P.530, просвет второй антенны, отображение на профиле и в отчёте |
| Итог | Вердикт простыми словами, рекомендации (высоты антенн, ACM, поляризация, разнесённый приём, наведение), азимуты и углы места, азимут по компасу |
| Справочник | ППУ — приёмо-передающие устройства (таблицы режимов) и антенны (диаметр, коэффициент усиления по рабочим частотам) |
| Отчёты | PDF по пролёту или по всему проекту со сводкой; шрифт с кириллицей встроен |
| Карта | OpenStreetMap, 2ГИС, рельеф OpenTopoMap, спутник Esri, светлая и тёмная CARTO; кэш просмотренных участков для работы без сети |

## Структура

```
app/
  desktop/
    src/                 интерфейс (React + TypeScript)
      components/        панели, списки, диалоги
      map/               карта Leaflet, слой с кэшем тайлов
      data/              модель данных и расчёт (data/calc — без UI, с тестами)
      storage/           SQLite, экспорт/импорт JSON и CSV, диалоги файлов
      net/               сеть: HTTP, рельеф SRTM, поиск мест, состояние сети
      report/            генератор PDF (без внешних библиотек)
      brand/             логотип ОИР
    src-tauri/           нативная оболочка Tauri (Rust), права, иконки
    tests/               эталонные тесты расчёта и отчёта
  .github/workflows/     сборка установщиков в GitHub Actions
  README.md
  desktop/.env.example   необязательный ключ MapTiler
```

## Запуск для разработки

```bash
cd app/desktop
npm install
npm test            # эталонные тесты расчёта (DRRL: Скумбрия, Мельниково — Шегарка)
npm run app:dev     # открывает окно программы с горячей перезагрузкой
```

`npm run dev` открывает интерфейс в обычном браузере (данные тогда хранятся в браузере), удобно для правки вёрстки.

## Сборка установщиков

**macOS** (на Mac):

```bash
cd app/desktop
npm install
rustup target add aarch64-apple-darwin x86_64-apple-darwin
npm run app:build:mac
# → src-tauri/target/universal-apple-darwin/release/bundle/dmg/OIR RRL Planner_1.0.0_universal.dmg
```

**Windows** (на ПК с Windows):

```powershell
cd app\desktop
npm install
npm run app:build:win
# → src-tauri\target\release\bundle\msi\OIR RRL Planner_1.0.0_x64_ru-RU.msi
# → src-tauri\target\release\bundle\nsis\OIR RRL Planner_1.0.0_x64-setup.exe
```

`.dmg` собирается только на Mac, `.msi`/`.exe` — только на Windows.

**Без своих машин — через GitHub Actions.** Загрузите папку `app` в репозиторий GitHub (папка `app` — корень репозитория), откройте вкладку **Actions → Build installers → Run workflow**. Через 10–15 минут установщики для обеих систем появятся в разделе **Artifacts**. Аккаунт GitHub нужен только тому, кто собирает; пользователям программы — нет.

## Подпись (по желанию)

Без подписи программа полностью работает, но при первом запуске система предупредит:

- **macOS:** «не удаётся проверить разработчика» → правый клик по программе → «Открыть» → «Открыть». Или `xattr -dr com.apple.quarantine "/Applications/OIR RRL Planner.app"`.
- **Windows:** SmartScreen «Windows защитил компьютер» → «Подробнее» → «Выполнить в любом случае».

Чтобы предупреждений не было:

- **macOS:** аккаунт Apple Developer (99 $ в год), сертификат «Developer ID Application». Перед сборкой задайте `APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_PASSWORD` (пароль приложения), `APPLE_TEAM_ID`: Tauri подпишет и отправит на нотаризацию.
- **Windows:** сертификат подписи кода (OV или EV). Укажите его отпечаток в `src-tauri/tauri.conf.json` → `bundle.windows.certificateThumbprint` и `digestAlgorithm: "sha256"`, `timestampUrl` вашего удостоверяющего центра.

В GitHub Actions те же значения задаются как секреты репозитория.

## Как проверить, что всё работает

1. Запустите программу. Список проектов пустой — тестовых данных нет. В справочнике есть шаблоны антенн и ППУ, их можно править или удалить.
2. Создайте проект, поставьте два объекта на карте (или по координатам), соедините их пролётом. Профиль рельефа, здания, лес и вода загрузятся сами (нужен интернет).
3. На вкладке «Итог» — вердикт и рекомендации, на «Подробно» — расчёт по шагам и выбор поляризации.
4. Нажмите «PDF», сохраните отчёт и откройте его; под графиком профиля — сохранение в PNG/JPEG.
5. Наведите курсор на точку объекта на карте → «Изменить положение», перетащите и сохраните.
6. Отключите интернет: карта показывает уже просмотренные участки, в шапке «Нет сети», расчёты и отчёты работают.
7. Закройте и откройте программу — всё сохранилось.

## Тестовый режим: каждая новая сборка — с пустым списком проектов

Пока программа в доработке, в `desktop/src/config.ts` включено `RESET_PROJECTS_ON_NEW_BUILD = true`: при первом запуске каждой новой сборки список проектов очищается, а прежние проекты сохраняются в файл `projects-backup-<дата>.json` рядом с базой данных (вернуть — «Файл» → «Импорт проекта или копии»). Справочник ППУ и антенн не трогается. Перед передачей программы в работу поставьте `false` — тогда обновления будут сохранять проекты.

## Где хранятся данные и как сделать бэкап

База данных — файл `rrl-planner.db`:

- **macOS:** `~/Library/Application Support/ru.oir.rrlplanner/rrl-planner.db`
- **Windows:** `%APPDATA%\ru.oir.rrlplanner\rrl-planner.db`

Точный путь показан в программе: кнопка с луной в шапке → «О программе и данных». Кэш карты хранится отдельно, в данных встроенного веб-движка (Windows: `%LOCALAPPDATA%\ru.oir.rrlplanner\EBWebView`, macOS: `~/Library/WebKit/ru.oir.rrlplanner`). Его можно удалить без потери данных: «О программе» → «Очистить кэш карты».

Бэкап:

- **из программы:** «Файл» → «Резервная копия всех данных» (один JSON-файл со всеми проектами и справочником); восстановление — «Файл» → «Импорт проекта или копии» (импорт добавляет записи и ничего не перезаписывает);
- **вручную:** при закрытой программе скопируйте файл `rrl-planner.db`.

Передать проект коллеге: «Файл» → «Экспорт проекта», коллега делает «Импорт проекта или копии».

## Сетевые обращения

Программа обращается **только** к этим адресам. Список зашит в `src-tauri/capabilities/default.json` (плагин HTTP не пустит никуда больше) и в политику безопасности окна (`tauri.conf.json`):

| Сервис | Зачем | Ключ |
|---|---|---|
| tile.openstreetmap.org | подложка OSM | не нужен |
| *.tile.opentopomap.org | подложка с рельефом | не нужен |
| server.arcgisonline.com | спутниковые снимки Esri | не нужен |
| *.basemaps.cartocdn.com | светлая и тёмная подложки CARTO | не нужен |
| *.maps.2gis.com | подложка 2ГИС | не нужен |
| nominatim.openstreetmap.org | поиск мест по названию | не нужен |
| api.opentopodata.org | высоты SRTM 30 м для профиля | не нужен |
| overpass-api.de | здания, лесные массивы и водоёмы на трассе (данные OpenStreetMap) | не нужен |
| api.maptiler.com | подложки MapTiler — только если задан ключ | необязательный |

У бесплатных сервисов есть правила использования: лимиты на число запросов (Nominatim — 1 запрос в секунду, OpenTopoData — 1000 запросов в день, Overpass — около 10 000 запросов в день) и запрет массового скачивания тайлов. Программа их соблюдает: поиск только по Enter, профиль — 1–3 запроса, здания, лес и вода — 1 запрос на пролёт, кэшируются только просмотренные участки. CARTO и Esri бесплатны для некоммерческого использования; для коммерческого в масштабе компании добавьте ключ MapTiler: скопируйте `desktop/.env.example` в `desktop/.env`, впишите `VITE_MAPTILER_KEY` и пересоберите. Без ключа всё работает на открытых подложках.

Проверка, что в коде нет посторонних обращений:

```bash
cd app/desktop
grep -rniE --exclude=fontdata.ts "claude|anthropic|artifact|analytics|telemetry|sentry|mixpanel|gtag|metrika" src src-tauri/src || echo "чисто"
grep -rhoE --exclude=fontdata.ts "https?://[a-zA-Z0-9.*{}-]+" src src-tauri/capabilities src-tauri/tauri.conf.json | sort -u
```

Второй список, кроме сервисов из таблицы, покажет только адреса, к которым программа сама не обращается: ссылки в подписях карты (openstreetmap.org, opentopomap.org, carto.com, leafletjs.com) и кнопки «Яндекс Карты» / «OpenStreetMap» в карточке объекты — они открываются в системном браузере только по нажатию; www.w3.org — пространство имён SVG; schema.tauri.app — схема конфигурации; 127.0.0.1 — локальный сервер режима разработки. Файл `fontdata.ts` исключён: в нём встроенный шрифт в base64, где случайно встречаются любые буквосочетания.

## Методика и точность

Потери в свободном пространстве, азимуты (WGS-84, Винсенти) и углы места рассчитываются точно. Дифракция — препятствие-нож (МСЭ-R P.526), многолучевые замирания — быстрый метод МСЭ-R P.530, дождь — P.530 и P.838, газы — P.676. Отражение от воды — двухлучевая модель: точка зеркального отражения на эквивалентной Земле, коэффициент отражения пресной воды по Френелю (проницаемость по Дебаю, как в P.527), фактор расходимости, рассеяние на волнении (σ = 0,1 м), подавление отражённого луча диаграммой антенн; худшее замирание ищется по k от kmin до 3. Сверхрефракция и волноводы над водой количественно не моделируются — программа выдаёт предупреждение и совет по запасу. Средняя скорость при адаптивной модуляции — формула (2.2) из диссертации Степанец И.В. «Исследование и разработка методов расчёта пропускной способности РРЛ с адаптивной модуляцией» (СПбГУТ, 2024); там же метод моментов для дождевых замираний в E-band по местной статистике (включается в «Климат и норма» для частот выше 57 ГГц). Методика НИИР (DRRL) учитывает больше факторов, поэтому проценты неготовности могут отличаться; для рабочего проекта сверяйте с DRRL или Pathloss. Эталонные проверки — в `desktop/tests/link.test.ts`.

**Вторая методика — ГОСТ Р 53363-2009** («Цифровые радиорелейные линии. Показатели качества. Методы расчёта»). Переключатель «Методика расчёта» в блоке «Климат и норма». По ГОСТ считаются: эквивалентный радиус Земли по климатическому району (приложение Б, с поправкой σ(R) для трасс короче 50 км), субрефракция (раздел 12), гладкие и селективные интерференционные замирания на пересечённых, горных и высокогорных трассах (раздел 13), пространственное и частотное разнесение (раздел 14), SESR и коэффициент неготовности от многолучёвости, дождя и субрефракции (разделы 15–18), интенсивность дождя по координатам середины пролёта и коэффициенту ξ (формула 16.1, приложение В). Не реализованы: слабопересечённые трассы и трассы над водой раздела 13.2 (считаются как пересечённые) и расчёт надёжности аппаратуры раздела 5 (вводится готовым значением). Опечатка в (13.23) — знак показателя — исправлена. Проверки — `desktop/tests/gost.test.ts`.
